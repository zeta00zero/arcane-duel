# Songs of the Symphony - browser prototype (v0.1, private)

Open `index.html` through any static web server (GitHub Pages works as-is). For local testing use
`python3 ../tools/serve.py` (it supports HTTP Range, which song previews need to seek).

## Controls (keyboard)
| Action | Keys |
|---|---|
| Move (left/right + depth up/down) | Arrow keys or WASD |
| Light attack | J |
| Heavy attack | K |
| Ultimate (when the Song Meter is full) | L |
| Pause | P or Esc |
| Menus / dialogue | Mouse/touch, or arrows + Enter (or J). Esc/K = back, Esc = skip |

Combos: J-J-J, J-J-K (finisher), K-K (kick into a launcher; juggle with more hits).

| `assets/video/hibiki_ultimate.mp4` | Ultimate move video (still a placeholder) |

Song titles, preview start time and preview length are in `js/data/characters.js` (`songs:`). Want more songs?
Add another line there. The phrase text shown on screen is `transform.phraseText`.
Videos: don't drop a raw export in; run it through `tools/encode_video.py` first (below).

## Character videos (transformation + ultimate) - for every new character
1. Put the original export somewhere outside `site/` (e.g. `user_video/kanade_transform_orig.mp4`). Never edit the original.
2. Make the web version (960x540 max, 30 fps, H.264 2-pass ~1.35 Mbit/s + AAC 128k, "faststart" so it starts while downloading):
   `python3 tools/encode_video.py user_video/kanade_transform_orig.mp4 site/assets/video/kanade_transform.mp4`
   It prints size, bitrate and sha1. Aim for about 4-5 MB per 25 s (use `--kbps 1000` for long videos).
   Do the same for the ultimate video.
3. Point the character at them in `js/data/characters.js`: `transform: { video: 'assets/video/kanade_transform.mp4', ... }` and
   `ultimate: { video: 'assets/video/kanade_ultimate.mp4', ... }`. No code change is needed.
4. The game's `VideoManager` (in `js/game.js`) does the rest: when the player confirms a character on the
   Character Select screen it starts downloading that character's videos (transformation first, then the ultimate),
   one `<video>` element per file, reused for every play. Before the fight it makes sure the ultimate is loaded too,
   so pressing L never waits. When a video is due it waits until it can play through to the end at the measured
   download speed (loading spinner with %); brief network hiccups only show the spinner and never restart or skip it.
   Skip / Enter / Esc always skip.
5. Test it on a slow connection: `python3 tests/video_throttle.py` (1.5 Mbit/s, 750 kbit/s and 400 kbit/s).

## Adding a character to the Character Select screen
`SOTS_DATA.roster` in `js/data/characters.js` is the grid: `columns` and a `slots` list. A slot is a character id
(playable) or `{ locked: true, name: 'Coming Soon' }`. The grid scrolls when there are more rows than fit.
Each character can set `select: { card, title, blurb, previewAnim, previewScale }` for its card and big animated preview.
Song Select then lists only that character's `songs`.

## Stage backgrounds (3 parallax layers)
A stage's `background.layers` in `js/data/missions.js` are drawn back to front, each tiled horizontally:
`{ src, y | bottom, parallax, scale }` - parallax 0 = fixed, 1 = moves with the ground. Stage 1 uses
`bg3_sky.jpg` (L3 sky, 0.06), `bg3_city.png` (L2 buildings/trees/lamps/fence with a transparent sky, 0.45) and
`bg3_ground.jpg` (L1 road where everyone stands, 1.0). They are built by `python3 tools/build_bg3.py`.

## Where things live
- `js/data/characters.js`: heroes (portraits, sprites, stats, moves/combos, transformation, ultimate, songs) and Noisy enemy stats. **A new hero is added with data only.**
- `js/data/missions.js`: missions, VN dialogue (story text) and waves.
- `js/data/sprite_meta.js`: generated by `tools/build_art.py` / `tools/build_anims.py`; don't edit by hand.
- `js/input.js`: input abstraction. Touch buttons can be added later with `Input.bindButton(el, 'light')`.
- `js/audio.js`: every sound goes through here, so the Options volume sliders (Master / Music / Voice-Video / Effects) apply everywhere.
- `js/game.js`: engine and scenes (Title, Missions, CharSelect, Songs, VN, Transform, Fight) and the `VideoManager`.
- `assets/img/`: art. In-game animation sheets are `hibiki_anim.png` (Hibiki transformed: idle, walk, jab, cross, kick, heavy, launcher, hurt, knockdown, ultimate pose, victory), `noisy_anim.png` and `boss_anim.png` (idle + 4-frame walk), plus `hibiki_uniform_px.png` (uniform idle) and `noisy_blob.png`. Older single-pose sheets (`hibiki_sheet.png`, `noisy_humanoid.png`, `noisy_boss.png`) are no longer referenced.
- Animations are data-driven: each anim/move in `characters.js` lists its frames with per-frame tick durations; a move's `hit` list marks the strike frames (the hitbox is live only there). Walk cycles use `stride` so frames advance with distance moved (no foot sliding). Rebuild sheets from `art/raw/anims` with `python3 tools/build_anims.py` (config `tools/anims.json`).

Debug: add `?god=1` to the URL to make Hibiki take no damage.
